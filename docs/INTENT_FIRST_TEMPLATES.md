# Intent-First Templates

This document provides a set of templates to help the team adopt the "Intent-First" philosophy in their daily work. These templates can be used for pull requests, new feature proposals, and bug reports.

---

## 1. Pull Request Template

Use this template for all pull requests to ensure that the intent behind the changes is clear and that the code has been thoroughly reviewed.

````markdown
### 1. Intent

**What is the user or business problem that this PR solves?**

[Provide a clear and concise description of the problem.]

**Why is this change being made?**

[Explain the reasoning behind the change and why it is necessary.]

### 2. Implementation

**What was the approach taken to solve the problem?**

[Describe the implementation details, including any trade-offs that were made.]

**How does this change affect the overall architecture?**

[Explain how this change fits into the larger system and any dependencies it has.]

### 3. Testing Strategy

**How has this change been tested?**

[Describe the testing that has been done, including unit tests, integration tests, and end-to-end tests.]

**What is the test coverage for this change?**

[Provide the test coverage percentage for the new code.]

### 4. Review Checklist

- [ ] The code follows the project's coding standards.
- [ ] The code is well-documented, especially in hard-to-understand areas.
- [ ] The change is covered by tests.
- [ ] The change has been tested locally.
- [ ] The change does not introduce any new security vulnerabilities.
````

## 2. New Feature Proposal Template

Use this template to propose new features. This will help to ensure that all new features are aligned with the product vision and that they provide real value to users.

````markdown
### 1. Problem Statement

**What is the user problem that this feature solves?**

[Provide a detailed description of the user problem, including who is affected and how.]

**How do users currently solve this problem?**

[Describe any workarounds that users are currently using.]

### 2. Proposed Solution

**What is the proposed solution?**

[Provide a high-level overview of the proposed feature.]

**How will this feature solve the user's problem?**

[Explain how the feature will address the user's pain points.]

### 3. Impact Assessment

**What is the expected impact of this feature?**

[Describe the expected impact on user experience, business metrics, and technical complexity.]

**How will we measure the success of this feature?**

[Define the key metrics that will be used to measure the success of the feature.]

### 4. MVP Scope

**What is the minimum viable product (MVP) for this feature?**

[Define the smallest possible version of the feature that can be built to validate the solution.]
````

## 3. Bug Report Template

Use this template to report bugs. This will help to ensure that all bug reports are clear, concise, and actionable.

````markdown
### 1. Description

**What is the bug?**

[Provide a clear and concise description of the bug.]

**What is the expected behavior?**

[Describe what you expected to happen.]

**What is the actual behavior?**

[Describe what actually happened.]

### 2. Steps to Reproduce

**How can the bug be reproduced?**

[Provide a step-by-step guide to reproducing the bug.]

### 3. Impact

**What is the impact of this bug?**

[Describe the impact of the bug on users and the business.]

**What is the severity of this bug?**

[High, Medium, or Low]

### 4. Environment

**What is the environment where the bug was found?**

[Provide details about the environment, such as the browser, operating system, and device.]
````
